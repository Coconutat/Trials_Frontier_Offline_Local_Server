# 幽灵存档（server/data/ghosts/）

每个子目录名就是赛道 id，里面放 `.bin` 幽灵文件。

## 文件格式（已实测解出）

```
偏移   类型   含义
0x00   u32    version = 3
0x04   u32    tag（每个文件不同，疑似校验和/唯一 id）
0x08   u32    解压后的长度
0x0c   u32    0
0x10   ...    zlib 流（首两字节恒为 78 da）
```

解压后的载荷（`zlib.decompress(d[16:])`）：

```
0x00   u32    = 1
0x04   u32    这一次跑的时间，单位毫秒
0x08   u32    帧数
0x0c   u32    = 0
0x10   ...    帧数据
```

自检判据：`len(zlib.decompress(open(p,'rb').read()[16:])) == struct.unpack_from('<I', open(p,'rb').read(), 8)[0]`。

例：`ghost_6f857655_1041.bin` 1888 字节 → 解压 2404 字节，
解压后 @0x04 = 0x6438 = 25656，与存档里 `highscores2` 中赛道 1041 的成绩
`[1041,25656,...]` 完全一致 ⇒ 确认 @0x04 就是该次跑的时间。

## 命名约定

游戏自己用的文件名是 `ghost_<玩家onlineId哈希的十六进制>_<赛道id>.bin`，
哈希 `0` 表示玩家自己（本机跑出来的最佳线路），其它值是别人的幽灵。

## 现在里面有什么

* `1041/ghost_6f857655_1041.bin` —— 从原版游戏设备上抓到的**别人的**幽灵（真数据）
* `66633/ghost_6f857655_66633.bin` —— 同上

请求进来时服务器按 `track_id` 找这里最新的一个 `.bin` 原样发回去；
目录为空就退回 `{"data": []}`（和以前一样，客户端能安全消化）。
